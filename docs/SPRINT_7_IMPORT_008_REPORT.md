# Sprint 7 - IMPORT-008 Implementation Report (Import/Export Round-Trip E2E)

*Date: 2026-11-12 - Scope: IMPORT-008 - No schema change, no new dependency.*
*Verified on the real browser/IndexedDB path (Playwright), not jsdom.*

## 1. Scope and verdict

IMPORT-008 is the acceptance gate for the whole import/export pipeline. The plan asks for one
thing: prove that `import HTML -> commit -> export JSON -> download -> re-import` leaves the
library identical, green in Chrome, Firefox and Edge. The task brief widened that to every
format the app can actually re-import (HTML and JSON), every relationship family (collections,
multi-collection membership, tags), every conflict path (new, live duplicate, soft-deleted
duplicate, per-conflict resolutions), malformed/partial input, and a multi-batch size.

The test work is split in two layers:

- `apps/web/src/import/roundtrip.test.ts` (new, 8 tests, `fake-indexeddb` + jsdom) - fast,
  deterministic import -> persist -> export -> re-import cycles with semantic snapshots.
- `e2e/import-export.spec.ts` (new, 4 tests) + `playwright.import-export.config.ts` (new) -
  the same journeys driven through the real Settings/Import/Export dialogs against real
  IndexedDB, with a downloaded file re-imported in a fresh browser context.

Writing the acceptance tests exposed six real fidelity defects that made the round-trip lossy
or lossy-looking. All six were fixed in the smallest place that owned the bug, with a
regression test each (section 4). No schema change, no new dependency, no broad refactor, no
change to unrelated parser/export behaviour.

**Verdict: PASS WITH CONDITIONS.** The plan's criterion is met: HTML -> JSON -> HTML/JSON
round-trips are green in Chromium, Firefox and Edge, including a 1,200-item multi-batch flow.
Conditions are the documented format losses (section 3), the untracked `raindrop.ts` seam
(section 5.1), and the fact that the 1,200-item browser flow is measured while 10,000 items is
still only unit-measured.

## 3. Fidelity by format

Comparison is a semantic snapshot: live resources only, keyed by URL, with collection and tag
names resolved through the join tables. Ids, `createdAt`, `updatedAt` and table row counts are
deliberately excluded because they are regenerated by design.

### 3.1 JSON (our Raindrop-compatible envelope) - full fidelity

| Field | After re-import |
| --- | --- |
| `url`, `title`, `description`, `notes`, `type` | preserved |
| `thumbnailUrl` (`cover`), `faviconUrl` | preserved |
| `domain`, `canonicalUrl` | recomputed from the URL (same value) |
| collections | every membership preserved via `collectionIds`; tree and parent names preserved |
| tags | per-resource tags preserved; tag names normalized identically |
| original `id` | regenerated (`crypto.randomUUID`) |
| `source` | becomes `"import"` (the export writes it, but the Raindrop parser sets its own constant) |
| `extractionStatus` / `extractionNotes` | reset to `"complete"` / `[]` |
| `lastOpenedAt` | lost (export writes it; the parser ignores it) |
| `createdAt` | preserved from `created` when usable; `updatedAt` is the commit time |

The snapshot test asserts equality on every preserved field and the E2E asserts the same
through real IndexedDB. `source`, extraction metadata and `lastOpenedAt` are excluded by
design, matching the losses documented here.

### 3.2 HTML (Netscape) - representable subset

Preserved: `url`, `title`, `description` (new `<DD>` support), `TAGS` -> tags, folder tree and
the bookmark's folder membership, `ADD_DATE`/`LAST_MODIFIED` attributes.

Lost (no Netscape field, or parser does not read it):

| Field | After re-import |
| --- | --- |
| `notes`, `thumbnailUrl`, `faviconUrl` | empty |
| `type` | `"other"` |
| `source` | `"import"` |
| `extractionStatus` / `extractionNotes` | `"complete"` / `[]` |
| `lastOpenedAt` | `null` |
| `createdAt` / `updatedAt` | import time (attributes written but not read) |
| extra memberships | only the first membership is written; the rest are gone |
| canonical URL / domain | recomputed from `url` |

The HTML E2E compares only this representable subset and separately asserts `notes === ""` and
`type === "other"`, so the loss is proven rather than assumed.

### 3.3 Markdown and CSV

Neither format has an import path in the app, so they are not part of the round-trip claim.
IMPORT-007 already covers their generation and escaping.

## 4. Defects found and fixed

Each defect was found by a failing new test, fixed at its owner, and is now pinned by a
regression assertion.

1. **HTML `&` corrupted on re-import** (IMPORT-007 known condition). The exporter left `&` raw;
   DOMPurify re-escaped it to `&amp;`, and the parser never decoded entities, so
   `?a=1&b=2` came back as `?a=1&amp;b=2`.
   Fix: `export/formats.ts` escapes `&` as `&amp;` in text and attributes; `import/parser.ts`
   gained a single-pass `decodeEntities` (named + decimal + hex) applied to href, title,
   description and tags.
   Regression: `formats.test.ts` round-trip URLs/description/tags; `roundtrip.test.ts` "decodes
   entities exactly once"; E2E HTML round-trip.
   Safety: decoding happens after sanitize and before URL validation, so `&#106;avascript:` is
   decoded and then rejected by `canonicalizeUrl`. `&amp;amp;` decodes to `&amp;`, never `&`.
2. **`TAGS` dropped at three layers.** DOMPurify's allowlist stripped the attribute, the parser
   ignored it, and `validateHtmlImport` hardcoded `tags: []`.
   Fix: allow `tags` in `ALLOWED_ATTR`, parse comma-separated `TAGS` per bookmark (deduped,
   added to the flat tag list), pass `meta.tags` through validation.
   Regression: `roundtrip.test.ts` HTML round-trip + entity test; E2E asserts
   `["AI Tools", "reading"]`.
3. **`<DD>` descriptions ignored.** The token scan had no `<DD>` branch.
   Fix: `<DD>` ends at the next structural tag and attaches to the preceding bookmark if it has
   no description yet.
   Regression: entity test (`"Desc & more & done"`) and the HTML round-trip description assert.
4. **JSON multi-collection membership ignored.** The export writes every membership in
   `collectionIds`, but `parseRaindropPayload` only reads the mirrored `collection`, so the
   second membership was lost.
   Fix: `validate.ts` merges `collectionIds` from the raw payload, keyed by canonical URL.
   Regression: JSON round-trip expects two memberships and the repeated-cycle test still
   expects `["Reading", "Tools"]`.
5. **JSON `faviconUrl` ignored.** Same seam: written by the export, not read by the parser.
   Fix: merged alongside `collectionIds`.
   Regression: JSON snapshot compares `faviconUrl`.
6. **Top-level tag records used `title`.** The parser reads `tag`/`name`, so exported tag rows
   produced `tag has no usable name` warnings and empty tag metadata.
   Fix: `export/json.ts` writes `{ _id, tag, count }`.
   Regression: `json.test.ts` expectation updated; `roundtrip.test.ts` asserts
   `validated.warnings` is empty for an exported file.

## 6. Limitations

1. **`apps/web/src/import/raindrop.ts` is untracked pre-existing work** and is absent from
   `HEAD`, although the committed `validate.ts` imports it. This task does not modify or commit
   it. The two export-only reads (`collectionIds`, `faviconUrl`) therefore live in
   `validate.ts` behind a `shortcut:` comment; they should move into the parser when that file
   is tracked.
2. **JSON does not preserve `source`, extraction metadata or `lastOpenedAt`** (section 3.1).
   They are written by the export but the parser does not read them. Fixing that would change
   `raindrop.ts`, which is outside this task's committable files.
3. **HTML cannot carry the full record** (section 3.2), including second and later memberships.
   This is a format limit, not a regression.
4. **No browser-level 10k measurement.** The largest real-browser flow is 1,200 items; 10k
   export is unit-measured and 600-item import is unit-measured across two batches.
5. **Synthetic fixtures.** The E2E generates its files under `testInfo.outputPath` instead of
   using `e2e/fixtures/`, because those fixtures are untracked pre-existing work. No fixture
   was modified.
6. **One run per browser.** The timings and green results are single runs on this machine; no
   repetition or p95 was computed, and no traces were retained (traces are
   `retain-on-failure`).
7. **Separate Playwright config.** The new spec runs under
   `playwright.import-export.config.ts` so the default suite (which includes the untracked
   Sprint 6 search benchmark) is not disturbed. CI must add this config explicitly.
8. **Markdown/CSV have no import path**, so they cannot be part of a round-trip claim.
